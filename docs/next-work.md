## 本轮目标与范围

减少重复排错、重复验收、等待维护者和源码/文档状态混乱，同时保住输入、信任、
隔离和恢复合同。沿用产品原则 §4.9，不再增加一套原则、审批或质量制度。

维护者已于 2026-09-16 授权执行以下整改。任务分成五个交付批次；
批次内完成必要诊断、实现、验证、清理和记录，不按一次报错或脚本运行拆交接。
既有 1.7 原型的授权和所属任务保持不变，但它不属于这轮流程优化的交付内容。

| 顺序 | 要交付的改进 | 完成标准 |
| --- | --- | --- |
| 1（清账完成） | 源码、任务与文档基线清楚 | 分清远端已合并、本地独有、并行任务所有；保留根区，使用干净来源 |
| 2（本链开发验证完成） | 验收工具能可靠执行并说明失败 | 收敛已知输入/完成/清理缺口；失败留存实际判定输入，能区分失败、未运行与未知 |
| 3（既有能力已核对） | 局部问题不再机械触发大范围重跑 | 离线验证分段/续验/身份拒绝；后续实际运行按此选范围，不新增框架 |
| 4 | 开发与诊断按风险和完整事件链推进 | 任务先有可观察合同和风险验证，修复先有可区分假设，一批闭合一个真实问题 |
| 5 | 人工协作、PR 与发布交接减少往返 | 自动工作先做完，人工只在就绪时介入；同链修复整体交付，材料和状态一次交接 |

1 先做；2、3 由既有独立工具维护任务协调收敛，可以作为同一个工程交付包。
4、5 主要改变日常执行方式，应从下一批立即采用，不等待工具全部修好，也不另建平台。
全部任务都不以重跑 1.6 正式验收证明完成。

## 2. 验收工具可靠性：一次闭合执行、观察与清理

既有“优化验收工具并隔离执行”任务负责工具修理。本批不是审计所有工具：
先核实现有修复，再处理仍有证据的同链缺口。涉及共享真机、HDC、WSL、端口或夹具时
先与当前占用任务交接；目录隔离不代表这些资源也隔离。

- [x] 收敛已知 `idle-reset`/异步命令完成观察问题。现有 Wi-Fi 收尾曾为
  `failed-harness`，app-relaunch 完成清理，但不证明原入口已修复。
  从本地保留的 §8.88 原始记录及[发布限制](release/1.6.0-status.md)
  定位提交、实际执行、完成信号、空闲确认和清理的首个错误边界；
  不盲目重发未知输入，不靠加长等待或无限重试修复。
- [x] 用实际辅助函数及现有反例验证必要前提、结果生产者/消费者和失败清理的合同。
  优先覆盖曾拖到长矩阵后才暴露的权限未就绪、清理成功字段不一致和准入路径遗漏。
  已修项只保留回归；仅修仍缺失的同链边界，不重新做整套准入框架。
- [x] 核对失败落盘是否保存“当次用于判断的原始输入及解析结果”，而不是事后重新取一份
  混合日志。区分产品失败、工具失败、环境未就绪、已确认第三方限制、未运行及证据不足；
  未知不得默认成 false 或 passed。保存最小必要的脱敏边界证据，不默认采集正文/秘密。
- [x] 用正常完成、完成信号迟到/缺失、观察失败、取消和清理失败的定向反例验证上述链路。
  离线能回答的先离线；仅剩真实调度/输入边界时安排一次命名真机场景。
  工具补丁在新一轮启动边界采用，不改旧失败、冻结报告或正在运行的工具。

**预算与停止：** 每个同链问题先定位和估算，再改行为；沿用两种实质修法/90 分钟
诊断检查点，计算分析、复验、CI、清理和等待的总投入，不因新局部报错重新计时。
若必须建设新调度框架或扩大到无关工具，停止并比较现有替代取证与延期。
不能因尚未自动化就无限延长这一批。

**验收：** 原反例能正确失败，修复后目标链成立，失败原因与残留状态可判断；
已有正确路径不退化。不能只以脚本返回零或正式矩阵偶然跑绿作为完成证明。

## 3. 减少重复构建与验收

本轮先验证已有机制，不新建框架。Agent continuation 70/71 项、分段编排 32 项、
证据读写及清理合同 58 项、真实 SSH Resume 块 10 项及材料来源检查通过。
已修正文档中“分段不能继承 Agent continuation”的过时句，限定为已有
`agent-split-R2` 合同；保留所有身份、清理和范围拒绝。这不是正式验收或设备行为证据。
SSH 与人工提示为已有实际代码的离线探针，未执行真实认证组或播放声音。
本批没有需要新建的续跑能力；结果见[整改记录](test-release-efficiency.md)。

- [x] 逐项核对现有自动/人工分段、有限 R2 续验、SSH 检查点及来源资格门。
  用现有报告或隔离 fixture 验证“可合法续验”和“身份/依赖不符必须拒绝”两类路径。
  不重造通用 resume 引擎，不把已有实现重新列为待开发。
- [x] 在现有验证入口和任务记录中明确产品候选、验收工具、发布材料三种身份及影响范围。
  对实际变化选择 L0–L3 或正式 R1–R4；文档/材料变更不自动重建产品，
  产品变化也不能冒用旧候选通过。重复准入清单确实继续造成误阻塞时才收敛其所有者。
- [ ] 对缺少受支持续跑的场景，先比较局部工具修理、受支持的等价人工取证和重跑成本；
  只补本次有净收益的最小能力。合法复用的阶段保持原身份，原始失败保留，
  不手工拼接 Pass。原因未知、清理失败或共享状态可能污染时先停止受影响工作。
- [ ] 正式长矩阵启动前先验证其关键环境前提和观察/清理通道；开发迭代先跑失败场景
  或高风险门，不先重复冗长稳定前缀。第三方已定位限制记录后继续独立验收，
  未知原因不能伪装成第三方豁免。

**验收：** 针对一份已有典型失败记录，能够说明哪些证据失效、哪些保留、实际支持的
恢复入口和最低成本的下一步；有定向验证，不靠重跑整个 1.6 矩阵演示。
不要求任意阶段都能续跑，不牺牲证据身份换取表面提速。

## 4. 开发与诊断按完整事件链交付

本批把既有原则用于下一项实际工作，不再写长篇制度或做一次全仓库架构重构。

- [x] 开始实现前，在该任务现有记录中写清用户结果、状态所有者、依赖公共合同、
  最可能推翻方案的假设、最小验证及结束条件。第三方能力和 fixture 先与真实语义
  对齐；不能把用户态 echo 当 PTY echo，或把“当前可见画面”当完整历史事件流。
- [x] 失败后先记录最后正确/最先错误的边界和下一次要区分的假设，建立最小复现，
  再改权威状态所有者。合成复现只证明对应机制，不扩大为所有自然故障的根因。
  怀疑采样改变时序时比较无观测、轻量计数和必要详细观测，不永久加重全链日志。
- [x] 把前提、调用、观察、失败/取消及清理的已证实缺口作为一批处理。
  第三方问题按最小复现、版本和安全证据反馈上游，不越界修改他方库；
  上游修复在固定版本验证。性能、资源释放和可读性检查随该链完成，
  不留到发布前集中发现，也不为微小收益增加抽象。
- [ ] 同一问题达到重审点时，必须给出简化、替换、延期或新诊断的实际决定；
  不只补一条记录后继续原循环。已经确认的产品决定不因困难反复要求维护者再确认。

**验收：** 下一批实际修复能追溯“假设—证据—修改—验证”，一个权威规则闭合问题，
删除失败尝试留下的多余补丁；无需阅读整个历史会话才能理解。

## 5. 人工协作、PR 与发布交接

- [x] 沿用并核对现有两段式入口：先完成自动工作和清理，到真正可以执行人工动作时
  再通知维护者。工具能做的输入、解锁和清理由工具完成；默认系统设备播放提示音
  和语音。不反复用合盖寻找不可控平台分支，不自行管理 WSL 生命周期。
- [x] PR 按完整、可审查和可回滚的事件链组织：不每发现一个局部报错就发一轮 PR，
  也不把所有无关改动攒成巨包。诊断期间只跑受影响检查，达到证据目标即交付，
  不以“再检查一遍”为由扩展范围。
- [ ] 发布前直接使用既有材料位置与命令，明确产品、工具、材料各自来源和用途；
  核对交接状态能否如实表达“已发布、已交付、待维护者提交”。
  已有手工等价记录继续有效；状态脚本表达缺口仅在下一次实际交接前有收益时补齐，
  不为它重开已完成发布。
- [x] 下一批结束时从已有记录简记：工具导致的中断、重复已通过工作耗时、
  可避免的维护者介入，以及本次整改投入。只看是否减少总成本；
  无数据记未知，不补跑采样、不建设指标平台。

**验收：** 自动任务不等待无必要的人工动作，人工就绪时不再花长时间准备，
交付后的来源、验证和剩余责任一次说清。不是要求每批都造一份新报告。

本轮已核对分段编排和既有本地实时提示 wrapper；其 SelfTest 证明四条提示精确选择、
重复抑制、零设备调用且不播放声音。默认设备和音量 100 的设置仍保留。
该 wrapper 固定旧轮次，不能直接再次执行；下一次人工段仅复用已证明的提示逻辑，
重新绑定当轮来源与就绪边界。暂不为未来人工操作开发通用提示框架。
本次命令完成修复已实践 §4 前三项及自动工作/整批交付；人工提示仅沿用上述离线证据，
不声称完成新的合盖/锁屏或发布交接。记录中保留一次编译修正及一次输入法校正后的
同场景复验；未重复整轮矩阵，零维护者操作。剩余条件项在下一次相应任务触发时执行，
不为勾完流程另造故障、人工动作或发布。
