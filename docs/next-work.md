维护者已确认 Ghostty/原生 GPU 替换与会话解耦方向。已有本地方案和架构讨论不等于
产品实现或运行验证；进入本批时先核对其独立提交状态，不混入本次发布状态 PR。

- [ ] 完成独立 API 24 原型及可行性结论：官方文字/GLES、Surface 生命周期、最小 IME、
  官方 Ghostty ARM64 构建和 ABI；一并闭合字符索引、彩色字形、分配器、无 Surface 的 VT
  消费、临时 VT 内存成本、解析/帧完成分离和销毁边界。取得运行证据后才进入产品接入；
  第三方文字库只在官方能力有明确缺口时引入。
- [ ] 原型通过后，一并交付最小会话解耦、原生终端集成及同机验收。显示层只接触终端
  交互合同，认证、`ltty>` 路由、Mosh 页面与退出策略归会话所有者；验证 SSH/Mosh、
  末尾输出和关闭语义。随后单 Pane SSH → Mosh/双 Pane → 完整既有交互；以正确性、
  恢复、性能与资源证据决定并完成替换。

不为旧 Web 实现另做完整架构改写。1.7 不包含本地 shell、HSL 直接接入、系统进程启动
或通用 Transport 插件框架。本次发布收尾不启动上述产品工作。

## 执行与停止规则

- 按质量策略只验证受影响链路；首个阻塞失败或未知结果停止矩阵，不盲目重发输入、
  自动重试模型或重复无关人工动作。已证实的第三方限制不阻断独立验收，也不是能力通过。
- 常规非阻塞工具问题记入测试效率记录，交独立维护；不热改冻结工具或顺手扩建框架。
- WSL 生命周期由维护者管理；可自动完成的真机输入、解锁和清理由工具完成。
  需人工配合时，在真正就绪后通过系统默认输出设备播放提示音和语音。
- MatePad 仍待合格物理测试机；Mosh remote command、高级网络、server 管理、文件传输、
  session manager 和 HSL 直接 transport 均需独立准入，不因版本计划自动授权。
