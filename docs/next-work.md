## 持续执行规则（不作为未完成 TODO）

沿用[质量策略](quality-strategy.md)和[编码指南](coding-guide.md)，不新增治理框架：

- 重试先说明新证据或改变的前提；使用入口已有的 `-PreviousAttemptId` 关联原失败。
  漏传时保留原报告并补充关联说明，不补写原字段、不因此再跑一轮。
- 缺少受支持续跑时，比较有限修理、等价人工取证和重跑成本；不手工拼接 Pass。
  正式长矩阵先核对环境、观察及清理通道，开发只跑受影响检查和最小稳定冒烟。
- 第三方限制须有定位证据；原因未知不能豁免。达到两种实质修法或 90 分钟未解决
  检查点时，实际选择简化、替换、延期或新假设，不只补记录后继续原循环。
- 自动工作和准备先完成，真正就绪才请求维护者操作；提示音与语音使用系统默认设备。
  已有实时提示 wrapper 的离线证据可复用，旧轮次身份不可照搬；不自行管理 WSL 生命周期。
- PR 按完整事件链交付，简记中断、重复成本和人工介入；达到证据目标即停止扩展。
  无数据记未知，不为流程优化另建指标平台或要求清零所有历史工具问题。

## 维护任务的执行与回报边界

实施前在对应活动项记录本批范围、预计投入和停止条件；先做无需设备的工作。
共享 HDC、真机、WSL、端口、签名或构建资源须与正在执行的任务明确交接，
独立目录不等于资源隔离。当前 1.7 原型由其原任务负责，本交接不授权接管或抢占资源。
依赖升级和输入法修理属于不同事件链，分开审查；同链的前提、观察和清理一起交付。
保留根区和冻结验收，Git/PR 使用既有身份与流程，验证后仅在下一轮启动边界采用。

维护任务收到交接后确认采用来源、当前执行项和受条件限制项；有成果时回报提交/PR、
实际测试及未运行项、共享资源清理和下一轮采用条件，同时更新此处对应状态。
本次文档交接不等于任何补丁已实施、正式资格通过或新发布获授权。
