# 1.7 原生终端同机性能与资源

2026-09-18 开发验证。原生路径在这台 PC 上的冷启动和空闲资源已有明显收益；热返回接近，
首次按键回显没有证明改善。本记录不关闭完整原生替换门，也不是正式发布验收。

## 方法与边界

- 同一 HAD-W32 ARM64 PC、系统 `6.1.0.135(SP60C00E100R13P3log)`、USB、窗口边界
  `[125,23][2911,1953]`、既有字号/字体设置、三个保留 Tab、第二 Tab 的单个可见本地 Pane。
- 基于 `1036320f3889d943a5e799bbd31776d8add30a63` 的同一开发工作树；四个测试签名 debug
  包仅更换冷/热诊断注入及 debug 的 `NATIVE_TERMINAL` 开关。Web 是本次集成代码的 Web
  分支，不是旧版发行包。构建后 306 个源文件及配置逐一核对还原，清单保存在本地证据中。
- 每个 renderer 各 20 次冷启动、20 次同进程热返回，共 80 个有效样本，无排除样本。
  顺序为 Native cold/warm、Web cold/warm，没有随机化 A/B 次序。复用系统应用中心真实
  图标、设备时钟与 T4 后的系统 ASCII `a` 注入；每组保留首字截图并目视核对。
- Native T4 需本地提示符写入、worker 消费及对应显示代际的成功 swap；首个空帧不算。
  T5 需当前输入所有者的 `a` 经本地 echo、消费后成功 swap。Web 复用既有 xterm render
  观测。二者都是绘制/提交观测，不是面板扫描时间。T3 含义不同，不直接比较其子阶段。
- 冷启动每次 force-stop，因此两条路径均显示既有“上次进程意外结束”恢复提示。这是
  固定测试条件，不是本轮出现崩溃；没有混入首次安装、迁移或真实远端会话恢复。

### 持续输出时的真实键盘输入

Native/Web 各两轮，每轮 12000×160、1,944,000 字节，按既有夹具的 50ms/16KiB 节奏
发送；输出期间通过 HDC 数值物理键派发 20 个 `?`。先核对远端完整命令再提交 Enter，
每轮结束核对远端输入恰为 20 字节、正文完整有序且零不匹配、20 个回显都在负载期间
完成消费和帧观察。Native 的消费序号与当前显示代际参与判定；Web 使用消费回调、
render 事件与后续帧回调，另核对缓冲尾行。四张尾部截图均人工检查正确。

| 路径 | 有效轮/按键 | 正文字节合计 | P50 | P95 | 最大值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Native | 2 / 40 | 3,888,000 | 28ms | 38ms | 48ms |
| Web WebGL | 2 / 40 | 3,888,000 | 35.3ms | 42.2ms | 58ms |
