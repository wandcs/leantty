## 用户问题

LeanTTY 断线态本地命令目前由 Session、Host/key 命令和文件传输分支分别输出，提示符、状态词、
颜色、换行与结束方式缺乏统一所有权。直接表现包括：

- 启动提示符 `ltty>` 重复且偏重，需要在不丢失本地态身份的前提下收敛；
- 未知命令整句红色且与下一步挤在一行，信息层级不专业；
- Host/key/SSH、帮助和 `put/get` 对成功、警告、取消、失败使用不同结构；
- 部分输出通过颜色表达语义，部分输出只有文字，缺少可复用的边界；
- 动态 Host、路径、远端 detail 和异常文字必须避免终端控制注入及秘密泄露。

目标不是“把命令行做得更彩”，而是建立一套可以长期约束新增命令的输出语言。

## 已确认的规范底线

以下内容来自现有产品原则和用户已明确表达的方向，不依赖提示符最终选型：

1. **文字是唯一语义，颜色只帮助扫描。** 去掉 ANSI 后，状态、结果和下一步仍完整。
2. **颜色少而稳定。** 同一颜色只表达一类语义，不为命令名、路径、大小、速度、耗时等普通数据
   随意上色，也不把整段正文染成红色或黄色。
3. **错误面向用户。** 第一部分说明发生了什么；存在可执行动作时，第二部分说明下一步。不得把
   原始异常、堆栈、内部临时路径、凭据或远端不可信控制文本当作用户说明。
4. **终态必须明确。** 进行中、已提交成功、警告、用户取消和失败是五种不同状态；取消不是失败，
   `Preparing`/进度也不能提前暗示成功。
5. **安静、紧凑、键盘优先。** 普通查询结果不重复“成功”，没有下一步时不强行增加提示语；不使用
   `[+]`、三角形等容易被理解为可展开控件的标记。
6. **固定字体允许有证据地使用单格 Unicode。** 不是一律退回 ASCII，但每个符号必须在 Regular、
   Bold 和真机固定字体中证明单格；无证据时使用 ASCII 文字。
7. **一个输出所有者。** 最终实现只能有一处提示符/token 定义；所有回到本地 IDLE 的分支使用同一
   结束规则，命令帮助和业务服务不得各自硬编码另一套提示符。

## 外部参考与 LeanTTY 取舍

- [Command Line Interface Guidelines](https://clig.dev/) 建议克制使用颜色、把预期错误改写成人能
  理解的说明，并给出可执行修复办法。LeanTTY 采用这些原则，但不照搬 stdout/stderr、管道和
  `NO_COLOR` 规则：本地命令直接写入始终交互的内嵌 xterm，不是通用 Unix CLI。
- [Cargo 终端配置](https://doc.rust-lang.org/cargo/reference/config.html#term) 将颜色、Unicode、
  进度和详细程度作为独立能力。LeanTTY 也应让颜色不改变状态机，让文件传输生命周期继续拥有
  进度和终态，而不是由样式代码推断业务状态。
- Cargo/rustc 的短状态词和诊断标签比整段染色更易扫描。LeanTTY 可以借鉴信息层级，但不输出
  `ERR`、`WARN`、内部错误码或开发日志，也不为了模仿竞品引入复杂渲染框架。

## 固定语义层

所有本地命令固定使用以下 token：

| 语义 | 建议文字 | 建议颜色 | 理由 |
| --- | --- | --- | --- |
| 就绪提示符 | 青色 `L` + 绿色 `>` | `L` 青色，`>` 绿色 | 把“本地环境身份”和“可以输入”分开 |
| 进行中/信息 | `Preparing`、`Note:` | 青色短标签，正文默认色 | 与现有传输进度一致，不暗示完成 |
| 成功 | 单格 `●`，正文默认色 | 绿色只用于标记 | 只在写操作已经提交后出现 |
| 警告 | `Warning:` | 黄色只用于标签 | 操作仍可继续或结果有降级 |
| 取消 | `Cancelled.` | 黄色短文字 | 不与失败混淆，不增加图标 |
| 错误 | `Error:` | 红色只用于标签 | 红色吸引注意，但正文保持可读 |
| 普通数据 | 无标签 | 默认前景色 | 帮助、表格、公钥、指纹、路径和统计保持安静 |

固定使用现有 ANSI 16 色：青 `36`、绿 `32`、黄 `33`、红 `31`，每个 token 后立即用 `0` reset；
不叠加 bold、dim、underline 或 true color。由 xterm 深浅主题决定最终色值，这比新增 RGB token
更简单，也与远端 TUI 的通用终端语义一致。

## 提示符

提示符同时承担“这是 LeanTTY 本地命令，不是远端 shell”和“现在可以输入”两种职责。固定格式为
青色 `L`、绿色 `>`、reset 和一个尾随空格：

```text
ESC[36mL ESC[32m> ESC[0mSPACE
```

`L` 和 `>` 各占固定字体的一格，总可见宽度两格。LeanTTY Chrome 已提供完整应用身份，提示符无需
重复 `ltty`；保留 `L` 又比只有 `>` 更容易识别从远端返回本地态。提示符不显示当前目录、Host、
用户名或状态；这些信息属于远端 shell、Chrome 或结构化状态，不塞入本地输入标记。

`ltty>` 与单独 `>` 已作为替代方案评估但未采用：前者重复且偏重，后者不能可靠区分本地态。

## 固定输出结构

错误固定为短第一行加可选第二行，不使用独立大标题：

```text
Error: Unknown command "frobnicate".
  Try: help
```

解析错误应保留具体用法：

```text
Error: Invalid command syntax.
  Usage: host rm <host-name>
```

不建议使用以下形式：

```text
Error
  Unknown command ...
  Try ...
```

它占用更多垂直空间，且 `Error` 容易像一个区块标题；也不建议把“发生了什么”和多个建议继续塞在
同一行。对于没有可靠下一步的失败，只显示一行明确事实，不编造建议。

绿点只给已提交写操作使用：

```text
● Host updated: work -> user@example.com.
```

`key list`、`host list`、`ssh-keygen -F`、公钥和帮助等查询结果不加绿点。文件传输仍可在绿点后显示
路径、大小、速度和耗时，但数据本身使用默认前景色。

普通正文使用 sentence case。说明句以句号结束；`Usage:`、命令、路径、表格和提示符不强加句号。
建议行固定缩进两个 ASCII 空格；不手工按列宽折行，由终端完成自然换行。没有可靠下一步时省略
第二行，不输出空 `Try:`。

## 命令与状态清单

实施必须逐项套用已确认标准：

| 范围 | 进行中/输入 | 成功或普通结果 | 警告/取消 | 错误与下一步 |
| --- | --- | --- | --- | --- |
| 启动、编辑、补全 | 统一提示符；多候选后重绘同一提示符 | 候选与截断说明 | 无 | 未知命令、不可用命令 |
| `help` | 帮助正文 | 完整指南链接 | 完整指南不可用应为非致命警告 | 未知 topic |
| `ssh` | 连接、密码、Identity passphrase、host key | 远端 shell 接管 | host key 变化需阻断 | 连接、认证、Host 解析、远端关闭 |
| `ssh-keygen`、`key` | 秘密输入 | 生成、导入、导出、删除、passphrase 更新；list/show/info 查询 | 旧语法、passphrase 不匹配、取消 | 不存在、冲突、解析、本地操作失败 |
| `host`、known-host | 无动画 | add/set/rm；list/find 查询 | 旧 `alias`、空结果 | 缺失、冲突、读写失败 |
| `ssh-copy-id` | SSH 连接与认证 | 安装完成和验证命令 | 无 | 超时、远端退出、连接失败 |
| `put/get` | `Preparing`、进度、`Finalizing` | 路径、大小、速度、耗时 | 自动改名、取消、清理异常 | 准备、权限、冲突、认证、网络、提交失败 |
| `scp` | 无 | 无 | 无 | 明确不支持并指向 `put/get` |
| `exit` | 无 | Pane 关闭 | 无 | 仍有远端连接时说明原因 |

## 安全与实现边界

最终样式层只拥有 ANSI token 和结构，不拥有命令状态机、业务文案或传输生命周期。进入用户诊断
前，动态 Host、路径、命令输入、远端 detail 和异常文字必须经过 `TerminalTextPolicy` 等价边界；
受控换行可以保留，ESC、C0/C1 与双向格式控制必须转义。日志继续用于开发定位，但用户输出不显示
秘密、堆栈或内部临时状态。

实现不得增加第二套 renderer、复杂富文本布局、额外图标字体、主题选项或命令协议。若统一输出
必须依赖这些内容，应停止并重新按可靠、简单、易用评审。

## 已确认决策

1. 提示符采用青色 `L` + 绿色 `>`，不再使用 `ltty>` 或单独 `>`。
2. 单格绿点用于所有“已提交写操作”；查询结果始终不使用。
3. 错误采用 `Error: 事实` + 可选缩进 `Try:/Usage:` 的紧凑结构；红色只作用于 `Error:`。
4. 黄色固定表示警告和取消，青色固定表示进行中和 `Note:`，正文保持默认前景色。

以上四项由用户于 2026-08-14 全部确认。任何 token 含义或提示符身份变化必须重新讨论；真机只
发现参数或对齐缺陷时，可以在不改变语义的前提下修正。
