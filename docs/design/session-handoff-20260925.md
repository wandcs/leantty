## 已确认的 Mosh 结论

- 无上下滚动符合当前 Mosh 临时页面合同，不在本轮擅自增加滚动历史。
- 上下键历史异常来自 WSL zsh 绑定；已经备份并改为内置 widget，新会话真机通过。
- WSL 的 `cat` 是 `bat` 别名，但 `\cat` 和 `/bin/cat` 绕过别名后指向同一程序。
  不能把路径写法当作两个不同库问题；交互 shell 状态和测试时序会影响表现。
- v0.1.1 的 U+FFFD 拒绝由 v0.1.2 修复；U+0605 宽度不一致由 v0.1.3 修复。
  两个修复有效，但不能推导出任意二进制输出问题已经解决。
- v0.1.3 真机固定字符样例通过，直接 `\cat /bin/ls` 在 23:08:10.783 返回
  `mosh_udp / protocol`，App PID 58811 未退出。是 Mosh 会话断开，不是 App 崩溃。
- 旧测试在输出后紧接 RIS 清屏，不能充分证明原主诉关闭。以后必须原样执行，
  先确认会话存活并独立提交后续输入，再决定是否清屏。

### 一次批量得到的七组 case

| ID | 触发 | 定性 |
|---|---|---|
| C01 | OSC 0/1/2 标题含分号 | 标题文本解析缺陷，UnsupportedOsc |
| C02 | SGR 5 闪烁 / SGR 8 隐藏 | 普通属性缺口，UnsupportedCsi；两个语义子例都保留 |
| C03 | DEC 私有模式 5 整屏反色及其复位 | 普通模式缺口，UnsupportedCsi；不同于 SGR 7 |
| C04 | 鼠标模式 1001 / 1015 开启 | 既有 profile 排除项，需库侧明确策略 |
| C05 | OSC 52 非法 Base64 `%%%` | 既有拒绝策略，不因标题修复放宽剪贴板边界 |
| C06 | `A` + 8 个 U+0301 | 超过每格 8 scalar 的已保留资源上限 |
| C07 | `A` + 7 个 U+1AB0 | 每格 UTF-8 存储边界，独立于 scalar 上限 |

建议库侧一批处理 C01–C03，明确 C04–C05 策略，保留 C06–C07 资源负例。
这不是授权 LeanTTY 自行实现七组兼容；更不能把所有错误吞掉或要求所有用例变成 Ok。
另有五类直接 HostBytes / 合同边界见完整报告，包含 OSC 的 ST 终止独立问题、
组合字符起点与分段、控制字符、其他 ESC/CSI、非法 UTF-8 / 不完整序列。
stock server 会归一化其中许多输入，不能把原始输入拒绝直接等同真实断连。

### 批量验证已做什么

- 原始交互 zsh + `\cat /bin/ls`：48 个差分，8 次拒绝全部归并 C01；继续读到

- 补充 277 个直接输入案例、271 个 stock 输出探针；三份录制共 325 帧，
  32 次拒绝全部按引用状态重放。没有遇到第一错就结束。
- 未改变生产错误处理的库副本：19 项独立 stock-server 正反例，12 个 Protocol、
  7 个正常；官方 Mosh 客户端的九个失败代表对照均正常完成后续命令。
- 原有库单测 124 项通过。已交付离线 runner 的 19 项和完整 277 项运行均完成，
  相对 v0.1.3 基线无差异；“无差异”表示复现了基线，不表示断连已修复。
- 已审计会话致命出口并分类网络、鉴权、资源和协议边界；不声称穷尽任意输入、
  OS 杀进程或所有资源耗尽组合，也不声称所有静态分支已动态覆盖。

诊断副本记录错误后推进解析，只用于找后续错误；资源拒绝后的状态可能截断。
