## 一、结论

LeanTTY 增加一份随安装包发布的离线 HTML 使用说明。用户在 LeanTTY 本地命令状态下
输入顶层 `help` 或 `?` 后，应用先完整输出该命令原有的终端帮助，再按需把当前版本说明
同步到公共 Download 目录下的 LeanTTY 包名文件夹，并在原有帮助末尾追加一行可通过
`Ctrl+Click` 打开的文件 URL。

当前包名为 `com.leantty.app`，目标文件为：

```text
Downloads/com.leantty.app/LeanTTY-User-Guide.html
```

对应的真机物理路径和可交给浏览器的 URI 形式由 HarmonyOS API 返回值决定，不在业务
代码中拼接 `/storage/Users/...`。2026-08-08 物理 PC 实测的应用侧规范 URI 为：

```text
file://docs/storage/Users/currentUser/Download/com.leantty.app/LeanTTY-User-Guide.html
```

系统浏览器接收后在地址栏规范化显示为 `file:///storage/Users/currentUser/Download/...`；
这两个展示不是业务层可以互换接受的白名单。ArkTS 只严格匹配当次 API 重新计算的前者。

本功能采用以下核心约束：

1. HTML 完全离线，不加载网络资源，不收集或上传数据。
2. 只在用户主动执行帮助命令时访问 Download，不在启动或后台自动生成。
3. 只管理包名目录中的固定指南文件和固定临时文件，不扫描 Download 或目录内其他文件。
4. 只允许 `Ctrl+Click` 打开本次功能计算出的固定指南 URI，不开放通用 `file://` 链接。
5. 原有终端帮助始终先显示；文件生成失败只影响末尾的完整指南链接。
6. 文件内容未变化时不重写；旧版只在确认属于 LeanTTY 后安全替换。
7. 指南完整支持中文和英文；系统语言明确为中文时首次显示中文，其他场景首次显示英文，
   文档内始终保留“中文 / English”切换且不保存另一套应用语言偏好。

## 二、产品判断

### 2.1 为什么要做

现有终端短帮助适合查询命令语法，但不适合承载完整的连接、Host、SSH Key、Tab、Pane、
搜索、快捷键和故障恢复说明。离线 HTML 提供更适合阅读和检索的层次，同时保留终端作为
唯一入口，不增加常驻菜单、设置页或联网文档服务。

它直接服务用户完成核心 TTY 工作：

- 新用户能从本地命令发现完整使用方法。
- 用户在断网、SSH 连接失败或浏览器无法访问互联网时仍可查看说明。
- 复杂内容进入独立文档后，终端命令级帮助仍可保持短而清楚。
- 文档随安装包发布，不依赖账号、云服务、统计或远程内容。

### 2.2 与产品原则的对应

| 原则 | 方案约束 |
| --- | --- |
| 用户信任不可交换 | 单文件离线资源；无网络请求、埋点、远程脚本和用户数据采集 |
| 可靠是底线 | 原有帮助不受影响；固定路径、确定版本判断、安全替换、失败可观察、真机门禁 |
| 简洁高效 | 复用已有 `help/?` 入口和 Downloads 授权；不新增设置、菜单或帮助状态 |
| 易用只优化核心路径 | 输出用户可定位的文件与可点击链接；命令级短帮助保持原位 |
| HarmonyOS 原生 | 使用公共 Download、系统授权和系统浏览器能力，不内置第二个文档浏览器 |

### 2.3 不采用的方案

| 方案 | 不采用原因 |
| --- | --- |
| 在线帮助站点 | 产生联网依赖、内容漂移和隐私边界，不满足离线恢复场景 |
| 在终端打印完整长文档 | 阅读和定位效率差，污染终端历史，并挤占命令级短帮助 |
| 新增应用内帮助页面 | 增加导航、生命周期和维护入口；系统浏览器已经能完成阅读 |
| 在启动时生成文件 | 无用户意图却申请权限和写盘，增加启动负担与打扰 |
| 把文件放在 Downloads 根 | 应用生成文件污染用户根目录，所有权和同名冲突边界较弱 |
| 使用 `Downloads/LeanTTY` | 显示名可能本地化或更名；包名才是稳定、唯一的应用身份 |
| 开放所有 `file://` 链接 | 远端内容可构造本地路径，扩大终端链接攻击面 |

## 三、命令和交互

### 3.1 命令边界

顶层帮助别名保持当前帮助正文，并在正文末尾追加完整指南链接：

```text
help
?
？
-h
--help
```

顶层别名的执行顺序固定为：

1. 立即输出该命令当前已有的完整终端帮助。
2. 同步离线 HTML；首次需要授权时，在原有帮助已经可见后请求系统权限。
3. 成功后在帮助末尾追加一行指南链接；失败后追加一行可恢复错误。
4. 最后一行输出完成后再恢复本地命令提示符，保证链接确实位于本次帮助结果末尾。

为避免改变命令级帮助的高频查询方式，以下命令继续只显示原有的针对性短帮助，不生成
HTML，也不追加完整指南链接：

```text
help ssh
help key
help host
ssh --help
ssh-keygen --help
```

只有 LeanTTY 尚未连接 SSH、正在解释本地命令的状态可以触发本功能。连接后的字符流
属于远端 TTY；远端 shell 中的 `help` 或 `?` 必须原样交给远端，不能触发本地文件操作。

### 3.2 成功输出

首次创建、更新完成或已经是最新版时，原有帮助正文完全不变，只在末尾增加一行：

```text
<existing help output>
Full user guide: LeanTTY-User-Guide.html (Ctrl+Click to open)
```

这是一条逻辑上的终端行；在较窄窗口中可以由终端自然换行，不拆成额外状态区块。实际
可点击范围只覆盖文件名 `LeanTTY-User-Guide.html`，提示文字不属于链接。OSC 8 链接目标仍保存平台
文件能力生成的完整、正确百分号编码 URI；不在可见文字中暴露长路径，也不能用文件名反推
物理路径。

“首次创建”“已经最新”“完成更新”不引入不同状态文案，也不输出 `User guide ready`。
用户只需要知道完整指南可用；同步差异进入日志，不增加帮助输出噪音。文件管理器中的
逻辑位置由 HTML 指南自身说明，不在终端再增加一行路径。

### 3.3 权限被拒绝或生成失败

只在执行顶层帮助命令时检查和申请 Download 访问权限。原有帮助必须在权限请求和文件
操作之前显示；失败时不撤回、不替换或重复输出原有帮助，只在末尾追加一行可恢复原因：

```text
<existing help output>
Full user guide unavailable: Downloads access was denied.
```

其他失败应区分“目录不可用、同名文件不属于 LeanTTY、写入失败、浏览器无法打开”等
用户可行动的原因。不得只显示错误码，也不得在失败后输出一个不可用链接。失败不属于
“回退到帮助”，因为原有帮助本来就是本次命令的主要结果，HTML 只是末尾增强。

### 3.4 并发行为

同一进程内多个 Pane 同时首次执行帮助命令时，各 Pane 立即显示自己的原有帮助正文，
随后共用一次正在进行的同步任务。每个发起命令的 Pane 最终都在末尾得到同一个成功链接
或明确错误，不并发申请权限或写同一个临时文件。该 single-flight 只封装这项真实并发，
不建设通用任务框架。

## 四、文件与目录模型

### 4.1 固定位置

运行时从应用上下文取得实际 `bundleName`，并在公共 Download 下解析：

```text
<Download>/<bundleName>/LeanTTY-User-Guide.html
```

当前发布结果预期为：

```text
Download/com.leantty.app/LeanTTY-User-Guide.html
```

如果包名未来变化，新安装包自然使用新的包名目录；业务代码不得把
`com.leantty.app` 复制成另一个独立常量。

### 4.2 为什么帮助使用包名目录，而用户文件仍使用根目录

使用说明是 LeanTTY 自动生成、可以由应用重新生成的派生文件；SSH Key 导出和未来
`get` 下载的是用户主动指定、需要直接发现和继续使用的用户文件。两类文件采用不同位置
不是两套文件系统模型，而是明确区分所有权：

| 文件 | 所有者和用途 | 位置 |
| --- | --- | --- |
| 离线使用说明 | LeanTTY 生成和更新的应用文件 | `Downloads/<bundleName>/` |
| SSH Key 导出 | 用户主动导出的结果 | Downloads 根 |
| 未来 `get` 文件 | 用户主动下载的结果 | Downloads 根 |

本方案不修改文件传输设计中“用户文件以 Downloads 为根”的决定。

### 4.3 管理边界

LeanTTY 只能操作以下明确目标：

```text
<bundleName>/LeanTTY-User-Guide.html
<bundleName>/.LeanTTY-User-Guide.html.tmp
```

不得：

- 枚举或索引整个 Download。
- 扫描包名目录中的其他文件。
- 因包名目录存在而假定其中全部内容都可以删除或覆盖。
- 在更新失败、应用升级或卸载时删除用户放入该目录的其他内容。
- 使用时间戳或随机编号持续生成重复的指南文件。

## 五、内置 HTML

### 5.1 单一标准版本

标准 HTML 作为安装包内的只读 rawfile 资源随版本发布。它是判断“最新版”的唯一权威
来源，不从网络下载，也不根据在线文档动态生成。

每次正式打包前，必须先按 [`release-process.md`](../release-process.md) 在开发 checkout
的 `release/X.Y.Z` 分支中重新生成并审查该 HTML。目标版本在 `CHANGELOG.md` 中已经确定的
全部用户可见变化是强制 delta 清单：新增能力进入对应最佳实践和参考章节，发生变化的
交互同步修订，未交付或已经移除的能力不得继续出现。中文默认版本和英文版本必须同时
更新；生成结果与其他发布文档一起提交、合并并推送后，才能冻结 release commit。不得在
detached production/review checkout 中临时生成一个未进入 Git 的正式包资源。

重新生成只保证事实来源更新，不代表中文已经可发布。每次生成后必须单独完成一次中文
“说人话”复核，再把同一字节复制到打包资源。复核按中文用户的任务顺序重写表达，不以英文
句序逐句对照，至少逐段确认：

- 先说用户要做什么，再说条件、限制和实现背景；主语、动作与下一步都明确。
- 优先使用常见中文动词和短句，删除“执行路径”“命令面”“最终值”等只有内部设计语境才
  自然的表达；确需使用 Host、Pane、Tab、SFTP 等产品术语时保持全文一致。
- 错误恢复文字必须告诉用户先检查什么、再执行什么，不只描述状态或重复错误名称。
- 命令、参数、路径、快捷键和必要英文专名保持原样；口语化不能改变安全边界、覆盖规则或
  已交付事实。
- 英文版本用于核对事实是否遗漏，不作为中文语序模板。复核者必须实际阅读中文首屏、操作
  步骤、错误恢复和本版本新增章节，不能只依赖搜索替换或自动化通过。

HTML 必须满足：

- 单个 UTF-8 文件。
- CSS 内嵌，无外部字体、图片、脚本、样式表或统计资源。
- 默认无 JavaScript。
- 使用限制性 Content Security Policy；默认拒绝外部内容，仅允许内联样式和必要的
  `data:` 图片资源。
- 不包含构建时间、生成时间等每次构建都会变化的动态字段。
- 建议不超过 100 KiB；实现设置合理的读取上限，避免异常同名文件造成无界内存读取。
- 包含固定的 LeanTTY 所有权标记和可读的指南修订号。

示意标记：

```html
<!-- leantty-owned-user-guide -->
<meta name="leantty-guide-revision" content="1">
```

修订号用于诊断和人工辨认；程序最终以安装包内标准字节内容为准，避免开发者更新正文
却忘记手动增加修订号。

### 5.2 内容结构

指南只覆盖已经发布、实际支持的产品能力：

1. 日常最佳实践：选中后右键或触摸板双指轻点复制、无选区时粘贴、
   `Ctrl+Click` 打开 URL、当前 Pane 搜索、首次指纹校验和远端 tmux 保活。
2. 快速连接：`ssh user@host`、端口、Identity 和 `.ssh/config` Host。
3. Agent CLI/TUI：远端 tmux/screen 的任务所有权、经核对的 Codex/Qwen 最小通知设置、
   Pi/OpenCode 当前限制，以及系统通知尽力而为而非任务状态的边界。
4. 主机密钥确认、密码、私钥和 keyboard-interactive 认证。
5. Host、Key、`ssh-keygen` 和 `ssh-copy-id` 的受控命令。
6. Tab、最多双 Pane、焦点和关闭行为。
7. 完整快捷键速查，以及 TUI 接管鼠标时的选区和链接操作。
8. 字号、透明度和当前菜单操作。
9. 断线、重连、取消和常见错误恢复。
10. 安全边界、Downloads 使用和隐私说明。
11. 应用版本和指南修订号。

页面的任务是帮助用户快速形成正确操作习惯，不承担产品宣传。首屏和第一个正文章节先
回答“现在怎样操作”，产品边界只在解释安全、持久化和故障恢复时按需出现，不使用功能
数量、营销口号或竞品比较组织内容。

不得提前描述 `next-work.md` 尚未交付的能力，也不得把 roadmap 或设计文档中的条件能力
写成用户已经可以使用的功能。

### 5.3 视觉与阅读体验

HTML 是阅读文档，不复制终端的半透明材质。采用克制的原生文档风格：

- 跟随浏览器 `prefers-color-scheme` 支持深色和浅色。
- 使用系统无衬线字体，命令和路径使用系统等宽字体。
- 正文行宽约 72–80 个字符，清楚的标题层级和充足行距。
- 命令示例可横向滚动，不因窄窗口强制断词。
- 颜色对比满足持续阅读，不使用模糊、透明背景、动画或装饰性渐变。
- 目录固定在文档顶部；不依赖 JavaScript 实现导航。

指南在同一个 HTML 中提供内容完整、结构一致的中文和英文版本，首次打开默认显示中文。
页面顶部提供“中文 / English”切换；两种语言共用样式和不需要翻译的命令示例，不拆成
两个可能发生版本漂移的文件。语言切换不使用 JavaScript、不联网，也不写入 Preferences
或其他持久状态；每次重新打开指南都回到中文。英文内容使用明确的 `lang="en"` 语义，
隐藏语言不进入布局和辅助功能阅读顺序。

## 六、最新版判断与安全更新

### 6.1 决策表

| 目标状态 | 行为 |
| --- | --- |
| 包名目录不存在 | 创建目录后写入当前指南 |
| 指南不存在 | 写入当前指南 |
| 现有字节与内置标准完全一致 | 复用，不改修改时间 |
| 有 LeanTTY 所有权标记但内容不同 | 视为旧版或损坏版本，安全替换 |
| 同名文件无所有权标记 | 不覆盖；保留已经输出的终端帮助，并在末尾报告冲突 |
| 临时文件存在 | 只处理固定临时文件，不扫描同类名称 |

逐字节比较对小型离线 HTML 的性能成本可以忽略，并能覆盖“修订号忘记更新”“文件被
截断”“用户修改了旧版 LeanTTY 指南”等情况。文件相同不得为了刷新时间戳而重写。

### 6.2 更新流程

更新必须优先保留当前可用版本：

1. 取得 Download 权限和运行时 bundleName。
2. 解析固定包名目录和目标文件，拒绝路径逃逸。
3. 读取内置标准资源。
4. 检查目标文件所有权和内容。
5. 把完整新内容写入同目录固定临时文件。
6. flush、关闭并确认写入完成。
7. 使用平台支持的安全替换把临时文件提交为正式文件。
8. 成功后计算可打开 URI 并输出。

不得直接 truncate 当前可用的指南后再写入。如果 HarmonyOS 公共 Download 不支持可靠的
同目录替换，必须在实现阶段重新评审提交策略，不能静默降级为可能留下半文件的写法。

发生失败时只清理 LeanTTY 固定临时文件；原正式文件保持不变。日志记录阶段和平台错误，
终端只显示用户可理解、可恢复的信息。

## 七、Ctrl+Click 与浏览器安全

### 7.1 链接生成

终端输出使用 OSC 8 超链接把“固定文件名”作为可见文本、“实际文件 URI”作为隐藏链接目标，使它不依赖
现有仅识别 HTTP/HTTPS 的 WebLinks 正则。普通点击不打开；只有现有终端规则定义的
`Ctrl+Click` 才向 ArkTS 发送链接激活事件。

不得把 `file://` 加入通用 WebLinks URL 正则。

### 7.2 唯一允许的本地链接

ArkTS 收到链接激活事件后必须重新计算当前允许的指南 URI，并执行严格相等比较：

- 协议、authority、规范化路径、文件名和编码结果必须一致。
- 目标必须位于当前 Download 的当前 bundleName 目录。
- 文件名只能是 `LeanTTY-User-Guide.html`。
- 包含 `..`、不同编码表示、查询参数、fragment、用户信息或额外尾随路径时拒绝。
- HTTP/HTTPS 继续使用现有浏览器安全策略，不因本功能改变。
- 其他 `file://`、`datashare://` 或自定义 URI 一律不由通用终端链接打开。

即使远端服务器输出伪造 OSC 8 链接，最多只能请求打开 LeanTTY 自己生成的固定指南，
不能选择任意本地文件。文件本身又通过包内标准内容和所有权规则维护，不执行脚本或联网。

### 7.3 系统打开方式

首选路径是使用 HarmonyOS 支持的文件 URI 和系统查看/浏览器能力打开 HTML，不固定某个
浏览器包名。实现阶段先做最小真机探针，确定：

1. 公共 Download HTML 的规范 URI 形式。
2. `context.openLink` 是否接受该 URI。
3. 若不接受，系统 `viewData`/HTML MIME 路由是否能交给浏览器。
4. 浏览器能否在其权限边界内读取并完整渲染文件。
5. 路径包含包名、连字符和百分号编码时是否一致。

若系统不能稳定把公共 Download HTML 交给浏览器，本功能不能以“只生成文件但链接不可用”
的状态完成。应回到方案评审，选择系统文件管理器打开或应用内只读页面，而不是扩大 URI
权限或指定私有浏览器接口。

## 八、实现边界

### 8.1 建议职责

| 现有边界 | 新增职责 |
| --- | --- |
| `CommandParser` | 保持现有顶层/命令级 help 语法判断，不负责文件或平台操作 |
| 本地命令执行 | 顶层 help 先输出原有帮助，再等待指南同步并追加一行；命令级 help 保持不变 |
| System Services | 封装 Download 授权、标准资源读取、文件同步和 URI 生成 |
| Terminal Surface | 输出 OSC 8 链接并维持现有 Ctrl+Click 手势 |
| BrowserLauncher | 保持 HTTP/HTTPS 规则；增加隔离的固定本地指南打开入口 |

文件所有权、内容比较和 URI 验证是明确且可测试的策略，可以拥有局部类型；不为这一个
文件建立通用文档管理器、下载框架、任意本地文件浏览器或插件式协议处理层。

### 8.2 性能边界

- 应用启动、SSH 连接和终端持续输出路径不增加工作。
- 只在顶层帮助命令触发时读取一个小型 rawfile 和一个固定目标文件。
- 内容一致时不写盘。
- 不保留文件监听器、缓存索引、后台任务或定时更新。
- WebGL 终端渲染路径不因离线 HTML 增加资源。
