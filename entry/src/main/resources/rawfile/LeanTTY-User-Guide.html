每天都会用到

先掌握六个高频动作。

先记住这六个操作，日常使用时就能少翻菜单、少重复输入。

COPY

选中后直接右键

选中文本后，鼠标右键或触摸板双指轻点即可复制；也可以按 Ctrl+C。

PASTE

无选区时右键粘贴

当前没有选区时，鼠标右键或触摸板双指轻点会粘贴；Ctrl+V 同样有效。

OPEN LINK

按住 Ctrl 点击 URL

按住 Ctrl 并单击链接即可交给系统浏览器；TUI 接管鼠标时改用 Ctrl+Shift+单击。

SEARCH

只搜索当前 Pane

按 Ctrl+Alt+F 搜索当前 Pane 中已经显示的终端内容，使用 Enter/Shift+Enter 前后跳转。

VERIFY

首次连接先核对指纹

通过已经信任的渠道核对服务器指纹；主机密钥变化时不要直接跳过警告。

KEEP WORK

长期任务放在远端 tmux

任务需要在应用退出、电脑休眠或网络波动后继续运行时，请把它放在远端 tmux 或 screen 中。

从这里开始

建立第一个会话

LeanTTY 启动后会显示本地 ltty> 提示符。输入连接命令即可进入远端 Shell。第一次连接时，LeanTTY 会先停下来，让你核对服务器身份。

  1. 01 / 连接 指定目标

    先输入用户名和主机；只有服务器有特殊要求时，再指定端口或私钥。

  2. 02 / 校验 核对指纹

    首次连接时，通过已经信任的渠道核对服务器返回的主机指纹。

  3. 03 / 工作 完成认证

    使用密码、已经验证的私钥，或按服务器提示完成键盘交互式认证。

直接连接

ssh user@example.com
ssh -p 2222 user@example.com
ssh -i id_work user@example.com

保存一个短名称

host add work user@example.com:2222
ssh work

保存的 Host 写在 ~/.ssh/config 中由 LeanTTY 管理的区域。连接前可用 ssh -G work 查看 LeanTTY 最终会采用哪些配置。

通过一个 SSH 跳板连接

host add jump gateway@jump.example.com
host add private deploy@target.example.com -J jump
ssh private
ssh -J jump deploy@target.example.com

LeanTTY 会分别校验跳板和目标的主机密钥，并分别完成认证；只有目标 PTY 就绪后才打开 终端。-J none 可让一次 ssh 绕过已保存的跳板，也可配合 host set 关闭该 Host 的跳板。首版只支持一个跳板，不支持 ProxyCommand 或逗号分隔的多跳链。

连接成功后，当前 Tab 会显示 用户@Host；如果通过保存的 Host 名称连接， 标题会保留这个短名称。正常退出远端 Shell、连接失败或取消连接后，标题会恢复为 ltty。

LeanTTY 负责连接，长期任务仍在远端运行。

如果工作必须跨越应用退出、重启或断网继续，请在远端使用 tmux 或 screen。

先确认，再信任

核对服务器身份，管好自己的密钥。

遇到新的主机密钥或主机密钥变化时，LeanTTY 一定会先询问或停止连接。你的私钥留在 本地；密码、口令和认证回答不会写入命令历史，也不会按普通终端文字显示。

主机密钥

首次连接会显示服务器返回的指纹并等待你的决定。接受前，应通过可信渠道核对。 如果主机密钥后来发生变化，LeanTTY 会停止连接。 

ssh-keygen -F example.com
ssh-keygen -R example.com
ssh-keygen -F [example.com]:2222
ssh-keygen -R [example.com]:2222
主机密钥变化不是普通提示。

先与服务器所有者确认变更，再删除旧记录并重新连接。

私钥

ssh-keygen -t ed25519 -f id_work -C work
key list
ssh-keygen -l -f id_work
ssh-copy-id -i id_work user@example.com
  • 生成 Ed25519 和 RSA-4096 密钥
  • 导入并使用加密私钥
  • 交互式修改私钥口令
  • 密码和键盘交互式（keyboard-interactive）认证
  • 按服务器要求连续尝试多种认证方式
  • 使用 Ctrl+C 明确取消

key export 会请求 Downloads 访问权限，并且不会覆盖私钥或对应的 .pub 文件。导出的私钥是敏感的用户文件；完成预定传输后，请及时移动 或删除。

克制的工作区

用 Tab 区分上下文，需要对照时再使用双 Pane。

每个 Tab 可以放一个或两个 Pane。每个 Pane 都有独立的 SSH Session 和终端， 焦点、搜索、输出和连接状态互不干扰。

任务行为
新建 Tab打开一个新的本地提示符，可独立建立 SSH Session。
拆分 Pane在当前 Tab 增加第二个 Pane；LeanTTY 不创建更深的布局。
搜索只搜索活动 Pane 当前已经显示的终端内容；空查询和无结果均显示 0/0。
BEL 提醒短暂强调来源 Tab；未查看的输出保留小型琥珀色标记。
关闭关闭已连接的 Pane 会断开该 Pane 的 SSH Session。

不离开键盘完成搜索

使用 Ctrl+Alt+F 打开搜索。按 Enter 前往 下一个结果，按 Shift+Enter 返回上一个结果，按 Esc 关闭。关闭后会恢复终端焦点，不会把搜索内容发送给远端。

外观服从内容

四点菜单提供关、低、中、高、极限五档透明度，也可以在这里调节字号。终端或 TUI 自己设置的背景色始终优先；系统不支持窗口透明时，LeanTTY 会自动使用不透明背景。

选区与 TUI 鼠标模式

选中文本后，鼠标右键或触摸板双指轻点会立即复制，也可以按 Ctrl+C；没有选区时，Ctrl+C 仍是终端中断， 右键或触摸板双指轻点则用于粘贴。当 tmux 或其他 TUI 接管鼠标后，按住 Shift 拖动可强制本地选择；使用 Ctrl+Shift+鼠标左键 打开链接。

Downloads 与 SFTP

在当前 Pane 传输一个文件。

put 和 get 复用 ssh 的 Host、端口、私钥、 主机校验和认证规则；远端必须提供 SFTP。 

put report.pdf user@example.com:/incoming/
put -p 2222 -i id_work builds/app.bin work:/incoming/app.bin
get user@example.com:/reports/latest.csv
get work:/reports/latest.csv reports/

本地路径相对于已授权的 Downloads；允许既有子目录，但不创建目录、不递归、不展开 通配符，也不接受多个源。目标以 / 结尾时必须是既有目录，并自动沿用源文件名； get 省略本地目标时也沿用远端文件名。

用 Tab 补全本地路径

  • 输入 put 或 get 的本地路径时按 Tab。./ 表示 Downloads 根目录，文件夹以 / 结尾。
  • 有多个匹配项时，第一次 Tab 显示候选，第二次开始选择；用 Tab、Shift+Tab 或方向键切换。
  • 选中项就是当前输入，可以直接继续输入、按空格或删除。Enter 只确认候选，Esc 撤销选择；进入文件夹后再按 Tab 补全下一层。

LeanTTY 从不覆盖已有文件。明确文件名冲突会失败；由 LeanTTY 选择下载名称时，会提交到 第一个可用的 name (n).ext。进度在单行显示百分比、已传输量、实时速度与 ETA， 完成后显示文件大小和耗时。无选区时 Ctrl+C 取消当前传输；有选区时 仍只复制。正常取消和受控关闭只清理本任务拥有的临时文件。

本地命令参考

本地命令不多，用法保持一致。

以下命令只在本地 ltty> 提示符下运行。连接成功后，输入归远端 Shell 所有。

命令用途

help <command>显示一个受支持命令的简短帮助。

数据默认留在本地

LeanTTY 会保留哪些数据。

LeanTTY 只保存下次安全连接确实需要的内容。终端输出、密码、口令和认证回答不会长期保存。

会保留不会保存
OpenSSH Host 配置密码和认证回答
已经信任的主机密钥口令和未提交的秘密输入
已经验证的密钥对命令历史
字号和主窗口位置应用退出后的 Tab、Pane、Session 与终端滚动记录
所选透明度档位账号、云工作区或使用情况遥测

Host 配置、可信主机密钥、已验证密钥对、字号和窗口位置使用加密的 HarmonyOS Asset Store 记录，并设计为在同一应用身份下跨普通卸载保留。透明度会在正常重启后 恢复，但不属于跨卸载保留的资产。

卸载不是完整的数据擦除命令。

卸载前，请删除你能识别的密钥、Host 和主机信任记录。

遇到问题时

先看提示，再按最短步骤恢复。

LeanTTY 会直接说明哪里失败。先看活动 Pane 里的提示，只处理当前问题；不要为了省一步 而跳过主机校验、覆盖保护或其他安全检查。

连接或认证看起来卡住了

按 Ctrl+C。连接和认证提示具有明确的取消路径，会返回 ltty>，且不会保留未完成的秘密输入。

服务器主机密钥发生变化

不要绕过警告。先与服务器所有者确认变化，执行 LeanTTY 显示的准确 ssh-keygen -R 命令，再重新连接并核对新指纹。

服务器反复要求密码

确认所选 Host 能解析出 User，并且 IdentityFile 指向 key list 中的密钥。使用 ssh -G <host-name> 查看最终值。

密钥导出失败

授予 Downloads 访问权限，并确认目标私钥文件名和对应的 .pub 文件都不存在。LeanTTY 不会覆盖已经导出的密钥。

休眠或网络变化后 SSH 断开

按界面提示重新连接。SSH 不能在网络切换后无感续接；需要在断线后继续运行的任务， 请放在远端 tmux 或 screen 中。

Use these every day

Learn these six moves first.

These interactions avoid menu hunting and repeated input. They are the shortest, most predictable ways to work in LeanTTY.

COPY

Select, then secondary-click

After selecting text, secondary-click—or two-finger tap the touchpad—to copy. Ctrl+C also works.

PASTE

Secondary-click with no selection

With no selection, secondary-click or two-finger tap to paste. Ctrl+V does the same.

OPEN LINK

Hold Ctrl and click a URL

Use Ctrl+Click to open a link in the system browser. When a TUI owns the mouse, use Ctrl+Shift+Click.

SEARCH

Search only the active pane

Press Ctrl+Alt+F, then use Enter/Shift+Enter to move through results.

VERIFY

Check the first fingerprint

Verify the server fingerprint through a trusted channel. Never skip a changed-host-key warning.

KEEP WORK

Keep long jobs in remote tmux

Run interruption-sensitive work in remote tmux or screen so it survives app exits, sleep and network changes.

Start here

Your first session

LeanTTY opens at a local ltty> prompt. One command takes you to a remote environment; the first connection pauses so you can verify who is on the other end.

  1. 01 / CONNECT Name the destination

    Enter a user and host. Add a port or identity only when the server requires it.

  2. 02 / VERIFY Check the fingerprint

    On first contact, compare the received fingerprint through a channel you trust.

  3. 03 / WORK Authenticate

    Use a password, verified private key or the server's keyboard-interactive flow.

Connect directly

ssh user@example.com
ssh -p 2222 user@example.com
ssh -i id_work user@example.com

Save a short name

host add work user@example.com:2222
ssh work

Saved hosts use LeanTTY's managed section of ~/.ssh/config. Inspect the supported effective values before connecting with ssh -G work.

Connect through one SSH jump host

host add jump gateway@jump.example.com
host add private deploy@target.example.com -J jump
ssh private
ssh -J jump deploy@target.example.com

LeanTTY verifies and authenticates the jump host and target separately, then opens the terminal only after the target PTY is ready. Use -J none to bypass a saved jump for one ssh command, or with host set to disable it for that Host. The first version supports one jump only; ProxyCommand and comma-separated chains are not supported.

After a successful connection, the current Tab shows user@Host and keeps a saved Host alias when one was used. After a normal remote-shell exit, a failed connection or a cancelled connection, the title returns to ltty.

LeanTTY is the entry point.

Use remote tmux or screen when work must survive an application exit, restart or network break.

Security before convenience

Trust the host. Control the identity.

LeanTTY never accepts a new or changed host key silently. Keys remain local, and secret input stays out of command history and normal terminal echo.

Host keys

A first connection shows the received fingerprint and waits for your decision. Verify it through a trusted channel before accepting. If the key changes later, LeanTTY stops the connection. 

ssh-keygen -F example.com
ssh-keygen -R example.com
ssh-keygen -F [example.com]:2222
ssh-keygen -R [example.com]:2222
A changed host key is not a routine prompt.

Confirm the change with the server owner before removing the old record and reconnecting.

Private keys

ssh-keygen -t ed25519 -f id_work -C work
key list
ssh-keygen -l -f id_work
ssh-copy-id -i id_work user@example.com
  • Ed25519 and RSA-4096 generation
  • Encrypted private-key import and use
  • Interactive passphrase change
  • Password and keyboard-interactive authentication
  • Multi-method authentication sequences
  • Explicit cancellation with Ctrl+C

key export asks for Downloads access and never overwrites either the private key or its .pub partner. Exported private keys are sensitive user-owned files; move or delete them after the intended transfer.

A bounded workspace

Tabs for context. Two panes when comparison helps.

A tab owns one or two panes. Every pane owns an independent SSH session and terminal surface, so focus, search, output and connection state do not leak across the workspace.

TaskBehavior
New tabStarts another independent local prompt and session path.
Split paneAdds one second pane to the current tab. LeanTTY does not create deeper layouts.
SearchSearches only the active pane's in-memory terminal surface. Empty and no-result queries show 0/0.
BEL attentionBriefly emphasizes the source tab; unattended output keeps a small amber marker until visited.
CloseClosing a connected pane disconnects that pane's SSH session.

Search without leaving the keyboard

Open search with Ctrl+Alt+F. Press Enter for the next result, Shift+Enter for the previous result and Esc to close. Closing search restores terminal focus without sending the query to the remote session.

Appearance stays secondary to content

The four-dot menu contains five transparency levels—Off, Low, Medium, High and Extreme—and a matching font-size stepper. Explicit terminal or TUI background colors remain authoritative. Platforms that cannot enable transparency fall back to an opaque surface.

Selection and TUI mouse mode

After selecting text, secondary-click—or two-finger tap the touchpad—to copy immediately; you can also press Ctrl+C. Without a selection, Ctrl+C remains terminal interrupt, while secondary-click or two-finger tap pastes. When tmux or another TUI owns the mouse, hold Shift while dragging to force local selection, or use Ctrl+Shift+Left click to open a link.

Downloads and SFTP

Transfer one file in the active pane.

put and get reuse the Host, port, Identity, host-key and authentication rules used by ssh. The remote endpoint must provide SFTP. 

put report.pdf user@example.com:/incoming/
put -p 2222 -i id_work builds/app.bin work:/incoming/app.bin
get user@example.com:/reports/latest.csv
get work:/reports/latest.csv reports/

Local paths are relative to the authorized Downloads tree. Existing subdirectories are allowed, but LeanTTY does not create directories, recurse, expand wildcards or accept multiple sources. A target ending in / must be an existing directory and keeps the source basename; omitting the local get target also keeps the remote basename.

Complete local paths with Tab

  • Press Tab while entering a local path for put or get. ./ names the Downloads root, and directories end in /.
  • With multiple matches, the first Tab shows the list and the second starts selection. Move with Tab, Shift+Tab or the arrow keys.
  • The selected match is now your input, so you can keep typing, add a space or delete text. Enter confirms it without running the command; Esc undoes the selection. Press Tab again inside a directory to complete the next level.

LeanTTY never overwrites an existing file. An explicit name conflict fails; when LeanTTY chooses a download name, it commits to the first available name (n).ext. One progress line shows percentage, transferred size, live speed and ETA, and completion reports size and elapsed time. Without a selection, Ctrl+C cancels the active transfer; with a selection, it only copies. Normal cancellation and confirmed close clean only this task's temporary file.

Local by default

What stays. What does not.

LeanTTY keeps the minimum durable state required to reconnect safely. Terminal content and authentication secrets are not part of that durable state.

RetainedNot intentionally retained
OpenSSH host configurationPasswords and authentication answers
Trusted host keysPassphrases and partial secret input
Verified key pairsCommand history
Font size and window rectangleTabs, panes, sessions and terminal scrollback after exit
Selected transparency levelAccount, cloud workspace or usage telemetry

Host configuration, trusted host keys, verified key pairs, font size and window geometry use encrypted HarmonyOS Asset Store records designed to survive a normal uninstall for the same app identity. Transparency is restored after restart but is not an uninstall-surviving asset.

Uninstall is not a complete data-erasure command.

Remove known keys, Hosts and trusted-host records you can identify before uninstalling.

When something stops

Recover without guessing.

LeanTTY surfaces failures instead of hiding them. Start with the message in the active pane and use the smallest recovery action that preserves trust.

Connection or authentication appears stuck

Press Ctrl+C. Connecting and authentication prompts have an explicit cancellation path and return to ltty> without retaining partial secret input.

The server's host key changed

Do not bypass the warning. Verify the change with the server owner, run the exact ssh-keygen -R command shown by LeanTTY, then reconnect and inspect the new fingerprint before accepting it.

Password keeps being requested

Confirm that the selected Host resolves a User and that its IdentityFile names a key shown by key list. Use ssh -G <host-name> to inspect the effective supported values.

Key export failed

Grant Downloads access and make sure neither the chosen private-key basename nor its .pub partner already exists. LeanTTY does not overwrite exported keys.

SSH disconnected after sleep or a network change

Use the visible reconnect path. SSH does not provide transparent roaming; keep durable work inside remote tmux or screen when interruptions matter.
